# Orionis MCP compatibility audit — 2026-11-14

## Source of truth and scope

The source review used the local Orionis Framework checkout at commit
`1e905f4f103d47c61789d877eba472a5bd97681b`, specifically `orionis/mcp`.
The Inspector baseline was `7cfdda3`. The framework was inspected, not modified.
This report describes the contracts found in source; runtime checks are separate
evidence and do not imply every application using Orionis has been tested.

The framework declares **MCP 2026-07-28 only** in
`protocol/constants.py`. Its dispatcher performs stateless, self-contained
requests. Consequently, adding `initialize`, `notifications/initialized`,
`Mcp-Session-Id`, a GET SSE connection or legacy version fallback would be
incompatible with this implementation. The Inspector already uses the correct
discovery-first architecture.

`McpProvider` loads application declarations and binds lifecycle shutdown;
`McpManager` owns the compiled registry and native routes. The compiler resolves
schemas, metadata, handlers and header mappings before serving requests. HTTP and
STDIO share `McpDispatcher`, which creates request-local contexts and applies
availability/authorization checks before invocation. The event bus owns bounded
subscription queues; `McpState` provides optional authenticated continuation
state. These are server responsibilities, not browser session features.

The [official base protocol](https://modelcontextprotocol.io/specification/2026-07-28/basic)
and [Streamable HTTP contract](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)
were consulted on the audit date. They confirm the stateless model, POST-scoped
streams and mirrored headers used by Orionis. An absent `resultType` can be
treated as `complete` for compatibility; Orionis itself emits it explicitly.

## Findings and changes

1. **Required prompt arguments were too restrictive.** The UI rejected `""`,
   although Orionis accepts any present string. The check now uses own-property
   presence. Missing values remain blocked, and non-string values remain invalid.
2. **Protocol errors could be mistaken for missing HTTP routes.** Orionis emits
   HTTP 404 with JSON-RPC `-32601` for unsupported methods. The error path must
   distinguish this from a missing route; it now preserves valid correlated
   protocol errors. Ordinary HTML/empty 404 responses remain HTTP diagnostics.
3. **Endpoint query values must not change operational catalogs.** Treating all
   query values as redaction substrings can alter legitimate tool names, enums,
   patterns and resource URIs. Operational catalogs now remain exact in the
   active connection, while records and exports are sanitized separately.
   Disconnect sanitizes retained catalog/test evidence before clearing the
   client's credential context. Descriptive titles/text and read-only schema
   previews are sanitized for display; forms retain exact operational enum
   values while sanitizing their descriptions.
4. **Incomplete operations needed explicit presentation.** A legal Orionis
   `input_required` response is not completed output. The result view now states
   that MRTR continuation is unavailable; validation remains `Not Tested` and no
   automatic retry occurs.
5. **Discovery and streaming boundaries lacked structural checks.** Known
   capability entries now require objects and boolean flags. Subscription
   acknowledgment must be a subset of the requested filters; subsequent events
   are checked against the accepted filters and duplicate acknowledgments are
   rejected. Completion data is checked for at most 100 strings, nonnegative
   integer totals and boolean `hasMore`. Invalid shapes produce controlled
   protocol diagnostics before enabling dependent operations.
6. **Initial endpoint links were unsupported.** `?mcp=` now goes through the same
   endpoint validation used for manual connections. It preloads a valid endpoint
   without sending requests until the user connects. Invalid/empty values leave
   the application usable and explain the problem; absence retains the ordinary
   empty endpoint flow. Nested query strings must be URL-encoded once.
7. **Query-bearing page URLs require privacy protection.** The endpoint may carry
   authentication in its own query. It must not be propagated to analytics or
   referrers. Static hosting introduces no SSRF request executor; browser requests
   still require the user's connection action and obey CORS.
8. **Body-reader cancellation could reject outside the request handler.** The
   real Orionis streaming exercise exposed an unhandled `AbortError` from the
   fire-and-forget reader cancellation. Both JSON and SSE abort callbacks now
   consume cancellation rejections; request cancellation remains visible as a
   controlled cancelled/timeout outcome.
9. **Redaction could manufacture protocol violations.** A valid endpoint with
   `?v=2` caused protocol metadata, headers and JSON-RPC `2.0` to be redacted and
   then reported as failures. Redacted UUID substrings could also duplicate the
   same request in history. Client-generated record identity and validated
   protocol discriminators are now preserved separately from sensitive payloads.
   Five regression cases cover numeric values, result discriminators, media types,
   method names and the protocol revision.
10. **Resource and prompt validation ran after display redaction.** A valid binary
    content value matching a credential could become `[REDACTED]` before its
    base64 validation, falsely failing the server. Like tool output validation,
    resource and prompt validators now receive the raw response synchronously;
    only verdicts are retained and display/export content remains sanitized.

These findings concern Inspector behavior. No discrepancy requiring a framework
source change was identified in the reviewed contracts. This is not a claim of
complete MCP certification or independent verification of every framework path.

## Security and operational limits

HTTP and HTTPS endpoints are supported, including ports, local hosts and internal
networks subject to the browser's policies. URL userinfo, fragments and unsupported
schemes are rejected. There is no server-side URL fetcher or proxy, so no new
server-side SSRF surface is added by `?mcp=`. A configured endpoint is still an
untrusted server: its schemas and results cannot execute page scripts, load remote
schema references or start tool calls automatically.

No OAuth acquisition, STDIO, extension execution, task orchestration, sampling,
roots or elicitation UI is implemented. Applications requiring these features
need another client. Request-state-only MRTR continuation is also unsupported;
the Inspector preserves the response as incomplete evidence. The Inspector cannot
prove server-side authentication, cancellation rollback, Origin enforcement,
multi-worker isolation or production network reachability from browser results.

## Validation evidence

The new `tests/e2e/orionis-compatibility.spec.ts` exercises required empty prompt
arguments and visible, unreplayed `requestState` continuations. Endpoint-link
tests cover absence, empty/invalid input, supported encoded URLs and manual edits.
The framework-backed integration fixture uses the actual local compiler,
dispatcher and HTTP transport rather than inferring the Orionis wire format from
a handwritten mock.
